开发环境搭建

从零开始，手把手带你搭建 Zephyr RTOS 开发环境，运行第一个程序

安装 SDK 与工具链

搭建 Zephyr 开发环境就像装修一间厨房——你需要先装好水管和燃气（工具链），再摆好锅碗瓢盆（SDK），最后才能开始做菜（写代码）。整个过程虽然步骤不少，但只要按顺序来，一点都不难。

1. 安装 Python 和 pip

Zephyr 的构建系统 West 是用 Python 写的，所以 Python 是最基础的依赖。你需要 Python 3.8 或更高版本。大部分 Linux 发行版和 macOS 已经自带了 Python，Windows 用户需要手动安装。

bash 
# 检查 Python 版本
python3 --version

# 确保 pip 是最新的
python3 -m pip install --upgrade pip

2. 安装 West

West 是 Zephyr 的"管家工具"，它负责管理多个代码仓库（类似 git submodule 的升级版），还负责调用构建系统。你可以把它理解为一个专门为 Zephyr 定制的超级 Makefile。

bash 
# 安装 West
pip install west

3. 初始化 Zephyr 仓库

接下来用 West 把 Zephyr 的源码和相关模块都拉下来。这一步会下载不少代码，请确保网络通畅。

bash 
# 初始化 Zephyr 仓库（以 v3.7 为例）
west init zephyr-workspace -m https://github.com/zephyrproject-rtos/zephyr --mr v3.7-branch
cd zephyr-workspace

# 拉取所有依赖模块（这一步比较耗时，耐心等待）
west update

提示：west update 会下载几十个仓库，如果网络不稳定可能会中断。可以多次运行直到全部成功。国内用户建议配置代理或使用镜像源。

4. 安装 Python 依赖

bash 
# 安装 Zephyr 所需的 Python 包
pip install -r zephyr/scripts/requirements.txt

5. 安装 Zephyr SDK（工具链）

Zephyr SDK 包含了针对各种架构（ARM、RISC-V、x86 等）的交叉编译器、调试器和烧录工具。就像你需要不同的翻译官才能跟不同国家的人交流一样，你需要不同的编译器才能为不同的芯片生成代码。

bash 
# Linux / macOS：下载并安装 Zephyr SDK
cd ~
wget https://github.com/zephyrproject-rtos/sdk-ng/releases/download/v0.16.5/zephyr-sdk-0.16.5_linux-x86_64.tar.xz
tar xvf zephyr-sdk-0.16.5_linux-x86_64.tar.xz
cd zephyr-sdk-0.16.5

# 安装所有架构的工具链
./setup.sh

# 如果只需要 ARM 架构（大部分开发板是 ARM）
./setup.sh -t arm-zephyr-eabi
powershell 
# Windows：下载 Zephyr SDK 安装器
# 访问 https://github.com/zephyrproject-rtos/sdk-ng/releases
# 下载 zephyr-sdk-0.16.5_windows-x86_64.msi
# 双击运行安装器，选择安装路径（建议不要有空格和中文）
# 安装时勾选需要的架构（至少选 ARM）

6. 设置环境变量

最后一步，让系统知道 Zephyr 在哪里。

bash 
# Linux / macOS：在 ~/.bashrc 或 ~/.zshrc 中添加
export ZEPHYR_BASE=~/zephyr-workspace/zephyr
source ~/zephyr-workspace/zephyr/zephyr-env.sh
powershell 
# Windows：在系统环境变量中添加
# ZEPHYR_BASE = C:\zephyr-workspace\zephyr
# 或者在 PowerShell 中临时设置：
$env:ZEPHYR_BASE = "C:\zephyr-workspace\zephyr"
python zephyr/scripts/zephyr_env.py
💡 验证安装

运行 west --version 和 cmake --version 确认工具链已就绪。如果都能正常输出版本号，恭喜你，厨房装修完毕！

第一个 Hello World 程序

环境搭好了，是时候让开发板"说话"了！我们先创建一个最简单的 Blinky 程序——让 LED 灯闪烁，这是嵌入式世界的 "Hello World"。

项目结构

一个典型的 Zephyr 应用最少需要三个文件：

  • src/main.c — 程序源代码
  • prj.conf — 项目配置（开启/关闭功能模块）
  • CMakeLists.txt — 构建脚本（告诉 CMake 怎么编译）

main.c — 程序源码

c 
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>

#define LED0_NODE DT_ALIAS(led0)

static const struct gpio_dt_spec led = GPIO_DT_SPEC_GET(LED0_NODE, gpios);

int main(void)
{
    int ret;

    if (!gpio_is_ready_dt(&led)) {
        return -1;
    }

    ret = gpio_pin_configure_dt(&led, GPIO_OUTPUT_ACTIVE);
    if (ret < 0) {
        return -1;
    }

    while (1) {
        gpio_pin_toggle_dt(&led);
        printk("LED toggled!\n");
        k_msleep(1000);
    }

    return 0;
}

这段代码做了三件事：首先检查 GPIO 是否就绪，然后配置 LED 引脚为输出模式，最后在无限循环中每隔 1 秒切换 LED 状态并打印日志。k_msleep() 是 Zephyr 的延时函数，它会让当前线程休眠，CPU 可以去做别的事情——这比裸机程序里的 delay() 死等要优雅得多。

prj.conf — 项目配置

conf 
# 启用 GPIO 驱动
CONFIG_GPIO=y

# 启用 printk 打印输出
CONFIG_PRINTK=y

# 启用串口控制台（用于查看 printk 输出）
CONFIG_SERIAL=y

# 启用 UART 控制台
CONFIG_UART_CONSOLE=y

prj.conf 就像手机的"设置"App——你在这里开关各种功能。Zephyr 采用 Kconfig 机制，只编译你用到的模块，所以最终生成的固件非常精简。

CMakeLists.txt — 构建脚本

cmake 
cmake_minimum_required(VERSION 3.20.0)

find_package(Zephyr REQUIRED HINTS $ENV{ZEPHYR_BASE})
project(blinky)

target_sources(app PRIVATE src/main.c)

编译与烧录

万事俱备，开始编译！-b 参数指定目标开发板，Zephyr 会自动选择对应的工具链和设备树配置。

bash 
# 编译（以 nRF52840 DK 开发板为例）
west build -b nrf52840dk/nrf52840 -p auto

# 烧录到开发板
west flash

# 查看串口输出
# Linux:
minicom -D /dev/ttyACM0
# macOS:
minicom -D /dev/tty.usbmodem*
# Windows: 使用 PuTTY 或 Tera Term，波特率 115200

提示：-p auto 表示自动清理之前的构建缓存。如果你改了配置但编译结果没变化，试试加上这个参数。如果遇到莫名其妙的编译错误，也可以先删掉 build/ 目录再重新编译。

🎯 其他开发板的板名

常见开发板名称：nrf52840dk/nrf52840（Nordic）、stm32f429i_disc1（STM32）、esp32_devkitc/esp32/procpu（ESP32）。运行 west boards 可以查看所有支持的开发板列表。

VS Code 开发环境配置

虽然命令行能完成所有工作，但一个好的 IDE 能让你的开发效率翻倍。VS Code 是目前 Zephyr 开发最受欢迎的编辑器，配置好之后可以享受代码补全、跳转定义、一键编译、图形化调试等便利。

推荐扩展

  • C/C++（Microsoft）— 代码补全、语法高亮、跳转定义的基础
  • CMake Tools — CMake 语法支持、配置管理、一键构建
  • Cortex-Debug — ARM Cortex 芯片的图形化调试（断点、单步、变量查看）
  • Zephyr Tools（社区）— 提供 West 命令集成和设备树语法支持

C/C++ 智能提示配置

编译完成后，Zephyr 会在 build/ 目录下生成 compile_commands.json，这是让 VS Code 理解代码结构的关键文件。

json 
{
  "configurations": [
    {
      "name": "Zephyr",
      "compileCommands": "${workspaceFolder}/build/compile_commands.json",
      "includePath": [
        "${workspaceFolder}/zephyr/include",
        "${workspaceFolder}/zephyr/soc",
        "${workspaceFolder}/modules/**"
      ],
      "cStandard": "c99",
      "intelliSenseMode": "gcc-arm"
    }
  ],
  "version": 4
}

调试配置（launch.json）

调试嵌入式程序和调试普通软件不一样——你需要通过调试器（如 J-Link、ST-Link）连接到芯片，才能设断点、看变量。下面以 J-Link + nRF52840 为例：

json 
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Cortex Debug",
      "cwd": "${workspaceFolder}",
      "executable": "${workspaceFolder}/build/zephyr/zephyr.elf",
      "request": "launch",
      "type": "cortex-debug",
      "servertype": "jlink",
      "device": "nRF52840_xxAA",
      "interface": "swd",
      "runToEntryPoint": "main",
      "svdFile": "${workspaceFolder}/zephyr/dt/bindings/arm/nordic/nrf52840.svd"
    }
  ]
}

提示：如果你用的是 ST-Link 调试器，把 servertype 改为 "stlink"，device 改为对应的 STM32 型号即可。SVD 文件可以让你在调试时查看外设寄存器的值，非常方便。

一键编译任务

你还可以配置 VS Code 的 Task，实现快捷键一键编译：

json 
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "West Build",
      "type": "shell",
      "command": "west build -b nrf52840dk/nrf52840 -p auto",
      "group": {
        "kind": "build",
        "isDefault": true
      },
      "problemMatcher": "$gcc"
    },
    {
      "label": "West Flash",
      "type": "shell",
      "command": "west flash",
      "dependsOn": "West Build"
    }
  ]
}

💡 新手建议

如果你是第一次接触 Zephyr，推荐从 nRF52840 DK 开始。原因很简单：板载 J-Link 调试器省去了额外购买调试器的麻烦，Nordic 官方对 Zephyr 的支持最为完善，BLE 示例最多，遇到问题也最容易找到解决方案。等熟悉了再换其他板子也不迟。

常见安装问题与解决方案

搭建环境的过程中踩坑是正常的——几乎每个 Zephyr 新手都会遇到一些问题。下面列出最高频的问题和对应的解决办法，帮你少走弯路。

Python 版本过低

⚠️ 症状

运行 west 或 pip install 时报错，提示 Python 版本不兼容。

Zephyr 要求 Python 3.8+，但有些系统默认的 python 命令指向的是 Python 2.7。你可以用 python3 代替 python，或者通过 python3 --version 确认版本。

bash 
# Ubuntu 安装新版 Python
sudo apt install python3.10 python3-pip

# 用 python3 代替 python
alias python=python3

west 命令找不到

⚠️ 症状

安装了 West 但终端提示 west: command not found。

这通常是因为 pip 的安装路径不在系统 PATH 中。最简单的解决办法是用 python3 -m west 代替 west，或者把 pip 的 bin 目录加入 PATH。

bash 
# 查看 pip 安装路径
python3 -m pip show west

# 方法一：用 python -m 方式运行
python3 -m west init ...

# 方法二：添加到 PATH（Linux）
export PATH="$HOME/.local/bin:$PATH"

工具链错误

⚠️ 症状

编译时报错 zephyr-sdk-0.16.5/arm-zephyr-eabi/bin/arm-zephyr-eabi-gcc: No such file or directory。

说明 Zephyr SDK 没有安装或者路径不对。请确认你已经运行了 SDK 的 setup.sh（Linux/macOS）或安装了 MSI（Windows），并且 SDK 路径没有包含空格或中文字符。

bash 
# 重新运行 SDK 安装脚本
cd ~/zephyr-sdk-0.16.5
./setup.sh

# 确认工具链存在
ls ~/zephyr-sdk-0.16.5/arm-zephyr-eabi/bin/

CMake 版本过低

⚠️ 症状

编译时报错 CMake 3.20.0 or higher is required。

Zephyr 3.7 要求 CMake 3.20+，但 Ubuntu 20.04 自带的 CMake 版本只有 3.16。需要手动安装新版本：

bash 
# 通过 pip 安装最新 CMake（推荐）
pip install cmake --upgrade

# 或者从 Kitware 官方源安装（Ubuntu）
sudo apt remove cmake
pip3 install cmake --user

# 验证版本
cmake --version

Windows 权限问题

🚫 症状

Windows 上运行 west flash 或安装驱动时报权限错误。

Windows 上烧录开发板需要安装正确的驱动程序。Nordic 的开发板需要安装 nRF Connect for Desktop 中的 J-Link 驱动；STM32 Nucleo 需要 ST-Link 驱动。此外，部分操作需要以管理员权限运行终端。

  • 以管理员身份打开 PowerShell 或 CMD
  • 安装对应开发板的 USB 驱动
  • 确认设备管理器中能看到开发板
  • 如果使用 Zadig 替换了驱动，可能需要恢复默认驱动

网络代理设置

⚠️ 症状

west update 或 pip install 超时、连接失败。

国内访问 GitHub 和 PyPI 经常不稳定，需要配置代理或使用镜像：

bash 
# 设置 Git 代理
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 使用国内 PyPI 镜像
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 临时使用代理运行 west
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
west update

提示：如果你在公司网络环境中，可能还需要配置 Git 的 SSL 证书。运行 git config --global http.sslVerify false 可以临时跳过证书验证，但请注意安全风险，仅建议在内网环境中使用。
